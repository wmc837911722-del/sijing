# 已接受的技术决策

## ADR-001：独立开源产品与桌面优先

状态：已接受。用户选择自建主干并复用开源组件，随后要求第一版同时支持 Windows、macOS、Linux。

采用 Electron + React + TypeScript；CodeMirror 负责 Markdown 编辑，Cytoscape 负责关系图，Python 服务随桌面程序分发。界面与本地服务之间通过受限 IPC 代理通信。渲染器启用隔离和沙箱，不获得 Node、数据库凭据、任意文件系统或命令执行接口。

取舍：相比 Tauri，Electron 安装体积较大；当前无需引入 Rust，跨平台编辑器和调试环境一致。采用原生平台 CI 打包 Python 与 Electron，不以 Windows 交叉打包冒充其他平台验证。

## ADR-002：Markdown 内容与本地派生状态

状态：已接受。

Markdown 文件是知识正文。桌面版使用 SQLite 保存配置、任务、索引与查询结果，避免要求每位用户运行 PostgreSQL 服务。业务数据库是用户配置的外部只读数据源，和本地 SQLite 元数据分离。后续团队服务可实现 PostgreSQL 存储适配，首版不为此提前拆分微服务。

人工写入要求内容版本一致。生成的代码索引与人工笔记分开维护。文件路径必须在当前 Vault 中且不通过符号链接逃逸。外部工具修改笔记后派生索引可重新构建。

## ADR-003：模型、工具与知识分离

状态：已接受。

一个有界编排流程负责上下文收集和模型请求。确定性执行层负责数据源权限、SQL 校验、超时与结果限制。知识问答不访问数据库，数据问答显式选择数据源。工具接口复用于 UI 和 MCP，外部 AI 的检索及查询不依赖本应用模型。

不同模型供应商单独适配请求及 usage。稳定系统提示在前，相关知识按确定顺序排列，动态问题在后。仅展示供应商实际返回的缓存计量，缺失值保持未知；不把回答缓存或结果缓存等同于模型提示缓存。实时查询重新执行，报表固定引用一次查询结果与时间。

凭据通过操作系统密钥服务保存；若系统密钥服务不可用，仅当前会话可用并明确告知。仓库代码、Markdown 与数据库结果都视为数据，不可更改系统指令或扩大工具权限。

## ADR-004：发布边界

状态：首个开发预览版。

所有版本发布前必须分别记录代码构建、自动化测试、实际模型连通、真实数据库兼容性以及三个操作系统的运行验证状态。没有真实凭据时使用适配器测试，并明确区分模拟响应测试与真实供应商验证。应用第一次启动展示明确标记的示例内容；不把演示数据伪装为用户仓库分析结果。

初版 Git 更新检测覆盖代码文件索引，启用 AI 分析后可依据变更文件和已有来源进行有范围限制的业务笔记更新，并为人工编辑保留审阅候选。完整的跨文件业务影响传播、已部署版本绑定、批量业务笔记原子发布与协同编辑是后续硬化方向，不可声称已具备完整生产保障。

## ADR-005：图谱布局与交互绘制分离

状态：0.2.2 开发预览，Windows 实测。图谱继续使用 Cytoscape 管理节点、边和原生手势；d3-force 在专用 Web Worker 中执行力导向布局，替代阻塞主线程的同步布局。主线程每帧消费最新坐标，拖动节点的位置由指针优先控制。图谱更新保留已有坐标，筛选和窗口调整不触发全图重排。

支持 WebGL2 时使用 Cytoscape 的加速绘制；缺少图形支持时使用 Canvas。标签由独立 Canvas 按缩放比例淡入，并保持悬停名称可读，避免总览中的微缩文字和大批字形纹理初始化。保留原生双指操作，不通过禁用所有用户缩放来替换滚轮。

视角与布局缓存只在当前窗口中存在，按知识库和图谱作用域隔离，最多保留 12 份。未完成的布局在恢复时继续，已完成的布局保持静止；隐藏时暂停，卸载时销毁 Worker 和事件监听。遵循系统减少动态效果设置。实际测量与冷启动限制见 [GRAPH-PERFORMANCE.md](GRAPH-PERFORMANCE.md)，不承诺所有设备和任意规模的固定帧率。
