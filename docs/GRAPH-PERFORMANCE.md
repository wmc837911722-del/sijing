# 业务图谱交互与性能改进

版本：**0.2.2**。Windows 打包程序的功能、图谱生命周期、缓存恢复，以及 300、600 节点的必需检查已通过。打开大图谱仍有短暂初始化：两种规模的最长主线程任务分别为 126 ms、201 ms，尚未达到全部低于 100 ms 的严格质量目标。

这次调整集中在探索图谱时的连续性：拖动节点能带动关联节点，滚轮围绕指针平滑缩放，悬停时看清直接关系，筛选、阅读笔记和调整窗口后保留已经找到的位置。整体仍使用黑白灰主题。

## 已确认的问题

对 0.2.1 的真实 Electron 窗口进行了 20、300、600 节点测试。节点来自独立测试目录中的 Markdown，由实际后端索引；测试使用鼠标操作图谱，不是单独运行算法得到的数据。

| 原版规模 | 打开图谱期间最长主线程任务 | 已观察到的交互问题 |
| --- | ---: | --- |
| 20 个节点 | 63 ms | 拖动不带动邻居、滚轮没有输入事件之间的插值、筛选清除后视角变化、窗口缩放改变图谱倍率 |
| 300 个节点 | 1,790 ms | 打开时明显阻塞；拖动不带动邻居；筛选及从笔记返回后视角变化，返回后节点重新排列 |
| 600 个节点 | 6,799 ms | 打开时长时间阻塞；悬停未区分邻居和无关节点；拖动不带动邻居；滚轮没有平滑插值；筛选清除后视角变化 |

300 节点基线中，从笔记返回后，节点最大位移约 1,092 个图内单位。问题同时涉及布局计算占用主线程、重复重排破坏空间位置，以及缺少针对图谱探索的交互反馈。600 节点基线只完成了 JSON 中列出的检查，不能推断未记录的后续操作也已测试。

证据：[20 节点基线](../artifacts/ux-graph/baseline-20.json)、[300 节点基线](../artifacts/ux-graph/baseline-300.json)、[600 节点基线](../artifacts/ux-graph/baseline-600.json)。其中 `opening_wall_ms` 包含脚本等待与自动化开销，不作为首帧或可交互时间。

交互参考来自实际使用本机 **Obsidian 1.13.4**：在独立配置和 150 篇合成笔记上观察拖动、缩放、悬停、打开笔记和返回行为。没有读取用户笔记，也没有复制 Obsidian 的闭源实现。详见 [GRAPH-REFERENCE.md](GRAPH-REFERENCE.md)。

## 当前实现

- **将布局计算移到 Worker。** 力导向模拟在独立线程分批计算，用可转移坐标数组返回结果；界面每个动画帧最多消费一份最新结果。图更新或快速拖动产生的旧消息通过代次与修订号过滤，避免过期坐标覆盖当前操作。
- **绘制支持图形加速。** 可用时用 WebGL2 绘制节点与连线，否则回退 Canvas。文字由独立 Canvas 按缩放与悬停状态绘制；小于四分之一屏幕像素的布局位移累积后再提交，停止时提交精确坐标，减少无效重绘。
- **拖动产生关联反馈。** 被抓住的节点始终跟随鼠标，邻居继续参与模拟；释放后逐步松弛。页面隐藏时暂停，卸载时释放 Worker、观察器和事件监听。
- **缩放围绕指针连续变化。** 滚轮累积目标倍率，在动画帧内逼近目标，并保持指针对应的图内位置；平移、选择、窗口调整不主动重新适应全图。提供放大、缩小、适应窗口及键盘操作。
- **保留位置与视角。** 原节点保留坐标，新增节点优先放在已有邻居附近；筛选只控制可见性。离开时缓存节点位置、平移、倍率及布局状态，重新进入时恢复。已稳定的缓存同时让 Worker 从静止状态恢复，避免第一次拖动重新触发初始布局而导致跳动。缓存按 vault、全局或局部图谱、当前笔记区分，最多保留 12 份；它只存在于当前应用窗口内，退出应用后不会持久保存，也不会写进 Markdown。
- **降低总览文字密度。** 使用较小节点和细线，按连接数调整节点大小，低倍率隐藏难以阅读的标签。悬停突出当前节点、直接邻居和关联边，无关部分变暗；当前标签保持可读。键盘节点列表提供另一种打开笔记的方式。
- **照顾减少动态效果的设置。** 用户启用系统减少动态效果时，减少布局中间帧和视角动画。Worker 不可用时给出明确提示，仍可拖动、缩放、打开笔记。

## 测量口径与已知限制

- **冷启动仍有优化空间。** 严格的“打开图谱期间所有主线程任务不超过 100 ms”质量目标尚未达到；最终结果单独保留这项质量警告，不把它写成通过。本次必需检查的单个主线程任务上限为 500 ms，两项门槛分别报告。
- **RAF 不等于显示帧率。** `requestAnimationFrame` 间隔反映渲染线程的回调调度，不等于 GPU 实际呈现 FPS；没有 renderer JavaScript error 也不能证明画面流畅。必须结合主线程长任务、真实鼠标操作、坐标和视角变化、连续截图判断。原版滚轮阶段的 RAF P95 较低，仍然存在缩放插值缺失和打开阻塞。
- **回退测试有明确边界。** Canvas 回退通过受控注入让 `getContext('webgl2')` 返回 `null` 验证。这证明应用在 WebGL2 创建失败时能继续使用，不代表已经在真实无 GPU 设备上验收。
- **仅确认真实零尺寸画布的暂停与恢复。** 自动化中原生窗口最小化实际成功，但 `document.hidden` 仍为 `false`，不能据此声称覆盖了原生窗口 visibility 暂停。已验证的是将画布 CSS 尺寸实际变为零后，`ResizeObserver` 触发 Worker 暂停，并在恢复尺寸时继续未完成布局；稳定缓存不重新布局。受后台节流污染的位移采样不用于流畅性比较。
- **平台范围为本机 Windows。** macOS、Linux 尚未实机验证，不能据此承诺各平台、所有设备和更大图谱都具有相同表现。
