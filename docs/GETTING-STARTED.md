# 思径 · Sijing 使用入门

思径原名 BusinessMap。升级后名称与图标更新，原有知识库、配置和凭据继续使用；默认数据目录与 `BUSINESSMAP_*` 环境变量保持兼容。

先用自带示例完成「读业务 → 查数据 → 看报表」，再接入自己的模型和仓库。体验示例地图、运行示例 SQL 都不需要 API 密钥；示例内容和示例数据库不代表你的真实业务。

## 跟着界面引导操作

首次打开应用时，会自动显示引导，高亮当前介绍的区域。点击 **开始引导**，按 **下一步** 浏览文档、图谱、模型、仓库、数据库、AI 问答及可选的 MCP 连接；用 **上一步** 回看。

想动手体验时，先点击 **去操作** 暂停引导，完成操作后点击左下角 **继续引导** 回到刚才的位置。**暂时跳过** 或 **关闭引导** 也会保留当前位置；下次启动不会自动弹出，可从左下角 **使用引导** 或 **继续引导** 重新打开。

小窗口下，引导说明可能需要滚动；标题、关闭和上一步/下一步按钮始终保留。键盘用户可按 Tab 聚焦说明区域，再用方向键或 Page Down 阅读。点击 **去操作** 后，焦点会回到当前介绍的控件；在图谱上可直接使用键盘缩放或移动视角。

最后点击 **完成引导**；以后点击 **使用引导** 会从头开始，也可在引导中途点击 **从头开始**。引导不会自动添加配置、调用模型或执行 SQL，这些操作由你在页面中主动发起。

下文与引导介绍的功能对应。没有模型账号时可先跳到第 5 节，用示例数据库完成查询和报表。

## 1. 沿着一条业务阅读

打开左侧 **业务地图 → 文档**，在知识目录中选择 **订单流程**，点击正文里的 **退款规则** 链接。你会进入退款笔记，右侧 **反向链接** 会列出引用它的笔记。

这些内容保存在本地 Markdown 文件中。笔记里的 `[[业务/退款规则]]` 就是一条知识连接，文档、图谱和问答共用这些内容。

试着再从退款规则打开 **退款表**，看看业务规则怎样连接到数据字段。若你已经切换到自己的知识库，直接选择其中一篇有链接的笔记；不必找回示例。目录看不到时，点击顶部 **切换知识目录**；没有搜索结果时先清空搜索和标签筛选。

## 2. 用图谱探索关联

点击 **关系图谱**，试着拖动一个节点、滚轮缩放，再将鼠标停在节点上观察关联。点击节点会打开对应笔记。

成功标志是：你能从一个业务节点找到与它相连的另一篇笔记。找不到节点时，清除 **筛选节点…** 中的文字，并点击图谱右下角 **适应图谱大小**。也可使用底部 **节点列表 · 键盘导航** 打开笔记。

需要补充业务说明时，在 **文档** 中点击 **新建笔记**，填入名称，点击 **创建笔记**；再点击 **编辑 Markdown**，写入说明和已有笔记的 `[[双向链接]]`，最后点击 **保存**。保存后到图谱检查新连接。未保存的修改不会写入知识库。

## 3. 配置你想使用的模型

进入 **模型配置 → 添加模型**，选择 **服务预设**，按服务商提供的信息填写 **API 地址**、**模型 ID** 和 **API 密钥**，点击 **保存配置**。

在模型卡片上点击 **测试**，看到连接成功后，按需要点击 **启用**。卡片上的 **当前使用** 表示默认模型；在问答中还可以单独选择其他已配置的模型。测试会向该模型服务发送一次请求。

测试失败时，通过卡片上的 **编辑模型** 检查地址、模型名称和密钥。若卡片提示密钥仅本次会话可用，重启后需重新填写。**模型使用与缓存** 展示服务商实际返回的统计；缓存数据为「—」表示未返回该指标。

## 4. 从自己的代码生成业务地图

仓库功能需要系统安装 Git；SSH 还需要 OpenSSH 客户端。公司内网仓库需要这台电脑先连上公司网络或 VPN。

1. 进入 **仓库 → 接入仓库**，在 **仓库地址或本地路径** 填入公司的 Git 克隆地址，例如 `https://git.company.local/team/orders.git`（示例地址），或点击目录图标选择本地 Git 仓库。
2. 私有 HTTPS 仓库将 **认证方式** 设为 **用户名 + Token / 密码**，填入公司的 Git 用户名和只读 Token。点击 **测试连接**；成功后会显示分支列表，可选择需要分析的分支。测试是可选步骤，也可直接接入。
3. 点击 **接入仓库**，在 **任务记录** 中等待导入完成。导入只建立代码索引，还没有调用模型分析业务。
4. 在仓库卡片中绑定一个公司允许接收代码的模型，核对其服务地址和模型名称，再点击 **AI 分析**。此操作会将必要代码片段发送给绑定的模型；只绑定模型不会发送代码。
5. 分析完成后，回到 **业务地图** 阅读生成的业务笔记，并检查正文中的代码来源和分析范围。

成功标志是出现属于该仓库的业务笔记和来源依据。接入失败时先查看任务错误；认证失败可在仓库卡片的连接设置中更新凭据，保存后同步重试。编辑凭据时留空保留原凭据，勾选清除才会删除。系统凭据库不可用时，界面会提示凭据仅本次运行有效，重启后需要重新填写。同步失败保留已有业务地图。

如果公司提供 CA 证书或代理地址，在 **网络与信任设置** 中填写。证书验证失败时向管理员取得正确 CA，不需要关闭校验。网页登录状态不会自动授权 Git；Token 需要按公司平台要求完成授权。远程地址使用 HTTPS 或 SSH，普通 HTTP 仅允许本机测试。

SSH 仓库可填写 `git@git.company.local:team/orders.git`，选择 **使用 SSH Agent** 或 **指定 SSH 私钥文件**。有口令的密钥应先在系统 SSH Agent 中解锁。首次连接前，使用可信终端核对服务器指纹并登记 `known_hosts`；也可在高级设置中选择公司提供的已信任主机文件。应用不提供交互式 SSH 登录、跳板机或自定义 SSH 命令。公司环境依赖这些功能时，可先通过公司的 Git 客户端克隆，再接入本地目录。

切换默认模型不会改变仓库绑定；修改绑定模型的服务地址、平台类型或模型 ID 后，需要重新绑定再分析。升级前已经接入的仓库同样需要绑定，原有索引和笔记继续保留。模型连接失败时先回模型配置测试连接，再重试 **AI 分析**。

首次分析成功后，**自动 AI 更新** 会启用。将代码改动提交到 Git 后，可点击 **同步变更**，或在应用运行时等待后台检查。未提交的工作区改动不会作为新代码版本分析；退出应用后不会继续后台更新。

远程仓库后续同步复用保存的认证和分支；本地目录只观察当前已提交的 HEAD，远端拉取仍由你的 Git 客户端完成。可以用一次小改动验证：提交后同步，检查任务记录及笔记来源版本是否更新。

在 macOS 上，红色按钮只关闭窗口，应用和后台同步仍在运行；点击 Dock 图标可重新打开。需要停止应用时，使用 **思径 Sijing → 退出** 或 **⌘ Q**。Windows/Linux 关闭最后一个窗口即退出应用。

若代码更新与人工维护的笔记有冲突，到 **待审阅的业务更新 → 审阅变更** 对比两个版本。需要保留人工说明时，点击 **复制建议**，再到笔记编辑器手动合并；**以建议版本更新笔记** 会替换当前笔记。

## 5. 完成第一次查询和报表

进入 **数据库 → 数据源与查询**，选择 **演示数据库 · 示例订单**，点击 **执行查询**。默认 SQL 按渠道汇总所有示例订单的数量和金额：

```sql
SELECT
  channel,
  COUNT(*) AS order_count,
  SUM(amount) AS total_amount
FROM orders
GROUP BY channel
ORDER BY total_amount DESC
LIMIT 100;
```

结果应出现 `channel`、`order_count`、`total_amount` 三列。这只是全状态订单汇总，不是扣除退款后的净成交额。

点击 **生成报表**，填写 **报表标题** 为「示例渠道订单汇总」，将 **呈现方式** 选为 **柱状图与数据表**，再点击 **生成报表**。在 **报表** 中打开它，用 **数值指标** 切换订单数量或金额；展开 **统计口径与 SQL 来源** 核对原 SQL。

报表保存本次查询的结果快照，数据变化后需要重新查询并生成新报表。SQL 编辑后也要再次点击 **执行查询**，下方表格才会更新。

连接自己的数据时，点击 **添加数据源**：SQLite 选择已有数据库文件；PostgreSQL / MySQL 填入主机、端口、数据库名和只读账号。保存后点击 **测试连接**，查看右侧 **数据结构**。出现连接或表名错误时，先核对当前数据源及允许访问的表。远程数据库应使用仅有 SELECT 权限的账号。

## 6. 用问答处理业务问题

进入 **AI 问答**，按问题选择 **模型**、**仓库** 和 **模式**：

| 你要解决的问题 | 设置和示例 | 如何确认结果 |
| --- | --- | --- |
| 解释业务规则 | 模式选 **知识问答**，输入「订单退款需要满足哪些条件？」 | 打开回复中的知识来源，核对规则；此模式不执行 SQL |
| 查询实际数据 | 模式选 **只读问数**，再明确选择 **数据库**，输入「按渠道统计订单数量和金额」 | 查看返回的表格，展开 **查看执行的 SQL** 核对查询 |

按 **Enter** 发送，**Shift + Enter** 换行。示例提问适用于示例订单业务；接入自己的仓库后，换成该系统中的实际业务名称。

选择了仓库时，使用该仓库绑定的模型；模型不匹配时，点击提示中的 **使用绑定模型**。全库问答只向当前模型提供其获准读取的仓库笔记，切换模型后旧对话仍可见，但不同授权范围的历史不会发送给新模型。

没有模型时，知识问答会返回明确标注的本地笔记摘录；只读问数不会生成 SQL，也不会查询数据库，可以先用第 5 节的 SQL 工作台。如果模型要求确认时间范围、状态或统计口径，补充条件后再问。

查询成功后，可点击回复中的 **保存为报表**，选择呈现方式并保存，再通过 **已保存 · 查看报表** 打开。请求失败时可先 **重新加载对话** 确认已保存的结果，或用 **将问题放回输入框** 修改后重发。

## 7. 可选：让其他 AI 工具使用业务地图

在 **模型配置 → 连接其他 AI 工具** 中点击 **复制 MCP 配置**，粘贴到支持 MCP 的工具配置中，并按该工具的方式启用连接。使用界面提供的完整命令和参数。

可以让外部 AI「搜索退款相关业务笔记并列出来源」，检查它是否能读取当前知识库。连接后还可读取数据结构并执行只读查询；外部 AI 不需要使用思径内配置的模型。

仓库模型绑定约束思径内部的模型请求，不约束外部 MCP 工具的模型选择。连接公司知识库前，应确认外部工具使用的是公司允许的模型；手工复制并移除来源归属的笔记及数据库内容也不属于仓库绑定的授权范围。

连接失败时先检查复制出的程序路径。远程数据库密码若仅保存在桌面会话中，独立 MCP 进程无法读取；使用系统凭据库保存的密码才能共享给该进程。

完成后，尝试一个自己的任务：找到一条业务规则，打开其来源笔记，再按规则写清查询条件，生成一份能追溯到 SQL 的报表。
